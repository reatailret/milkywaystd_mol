# $mol & MAM Specification Viewer

Приложение для отображения спецификации фреймворка $mol и системы сборки MAM.

## Описание

Это приложение демонстрирует:
- Загрузку и отображение Markdown файлов
- Использование компонента `$mol_text` для рендеринга текста
- Настройку MAM для включения статических файлов в сборку через `.meta.tree`
- Базовую структуру приложения на $mol

## Структура файлов

```
mws/app/testspec/
├── index.html              # HTML точка входа
├── testspec.view.tree      # Декларативный шаблон UI
├── testspec.view.ts        # Логика загрузки spec.md
├── testspec.view.css       # Стили для отображения markdown
├── testspec.meta.tree      # Конфигурация деплоя (включает spec.md в сборку)
├── testspec.locale=en.json # Локализация
├── spec.md                 # Файл спецификации (копия из mws/app/spec/)
└── readme.md               # Этот файл
```

**Важно:** В MAM не требуется отдельный `package.json` для каждого модуля. Все модули используют общий `package.json` из корня проекта.

## Ключевые моменты реализации

### 1. Включение spec.md в сборку

Файл `testspec.meta.tree` содержит:
```
deploy \/mws/app/testspec/spec.md
```

Это указывает MAM включить `spec.md` в финальную сборку в папку `-/`. Без этого файл не будет доступен в production build.

### 2. Загрузка файла

В `testspec.view.ts`:
```typescript
@$mol_mem
spec_content() {
    // Путь с сохранённой структурой после deploy
    const response = this.$.$mol_fetch.text('mws/app/testspec/spec.md')
    return response
}
```

Метод использует `$mol_fetch.text()` для загрузки содержимого файла. **Важно:** путь соответствует структуре файла в `-/` после deploy (полный путь сохраняется).

### 3. Отображение контента

В `testspec.view.tree`:
```tree
<= Content $mol_text
    text <= spec_content \
```

Компонент `$mol_text` отображает текстовый контент с поддержкой базового форматирования.

## Запуск приложения

### Разработка

Из **корня проекта MAM**:

```bash
npm start
```

Откройте браузер: `http://localhost:9080/mws/app/testspec/-/test.html`

MAM автоматически скомпилирует модуль при первом обращении.

### Production сборка

Из **корня проекта MAM**:

```bash
npm start mws/app/testspec
```

Результат сборки будет в `mws/app/testspec/-/`

## Проверка что spec.md попал в билд

После сборки проверьте наличие файла:
```bash
ls mws/app/testspec/-/mws/app/testspec/spec.md
```

Структура в `-/`:
```
mws/app/testspec/-/
├── web.js
├── web.css
├── index.html
└── mws/                    ← Полный путь сохранён
    └── app/
        └── testspec/
            └── spec.md     ← Файл здесь
```

Файл копируется благодаря директиве `deploy` в `.meta.tree` **с сохранением полного пути**.

## Альтернативные подходы

### Использование hyoo/marked

Для более продвинутого отображения MarkedText (не Markdown) можно использовать:

```tree
<= Content $hyoo_marked
    text <= spec_content \
```

Однако `spec.md` написан в Markdown, поэтому для полноценного рендеринга нужен Markdown парсер.

### Встраивание контента напрямую

Вместо загрузки файла можно встроить контент в код:

```typescript
@$mol_mem
spec_content() {
    return `# Спецификация\n\n...`
}
```

Но это увеличит размер бандла и усложнит обновление документации.
